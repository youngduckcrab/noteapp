> 결론: **A를 바탕으로 한다(29점 대 21점).** B에서 11가지 요소를 옮기고, A에서 7가지를 고친다(4·5절).

## 1. 채점 방법

- 기준 7개, 각 1~5점(5 = 가장 좋음). 합계 35점.
- 근거는 초안 본문, 조사 문서, 그리고 이번 판정 때 1차 작업 트리(`/home/user/wt/{core,ink,editor,library,pdf,sync,infra}`, 읽기 전용)에서 직접 확인한 사실이다. 확인한 사실은 **[확인]**으로 적는다.
- 두 초안 모두 조사 권장안을 대부분 채택했다(각 부록 A). 같은 내용(M4 실연결 제외, `pageObject` 한 종류 + 모르는 `type` 보존, SYNC '모르는 종류 보류', FTS5 음절 바이그램 색인, ML Kit + 안드로이드 APK 첫 판정, `pencil_bridge` 직접 작성, `permission_handler` 제외, `functions/` 에뮬레이터까지)은 점수 차이를 만들지 않았다. 차이는 **새 기능 코드를 누가·어디에 두는가**와 그에 따른 계약 표면에서 났다.

## 3. 판정

- **A를 바탕으로 한다.** 1차 7개 영역이 모두 자기 동시 개발 몫을 끝냈고(각 `progress/<id>.md` — 남은 것은 통합 단계뿐), 2차 작업의 대부분이 '자기가 1차에 만든 코드를 넓히는 일'이 되는 A가 통합 위험과 총괄 운영 비용이 가장 작다.
- B의 핵심 장점(플러그인 격리, 엔진 교체 쉬움, 다음 라운드 확장)은 A도 서비스 패키지 3개(`media_io`·`ink_recognition`·`pencil_bridge`)와 포트(`AudioRecorderService`·`HandwritingRecognizer`·`MathRecognizer`·`InkShapeFitter`)로 대부분 얻는다. B가 추가로 얻는 '에디터 확장 SDK'는 이번 라운드의 규모(개인용, 기능 4묶음)에 비해 계약 비용이 크다.
- A의 약점 — 주제가 어색한 영역 배치(PDF가 오디오, LIBRARY가 인식, SYNC가 서버 함수), 영역 경계에서 갈리는 UX(녹음 패널·변환 창), 웹 녹음 끊김 대비를 P-B로 둔 것 — 은 B의 요소를 옮기고(4절) A를 고쳐서(5절) 줄인다. 영역 배치는 작업량 균형(기준 5)을 위해 그대로 둔다.
