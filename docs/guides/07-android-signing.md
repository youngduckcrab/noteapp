# 07. 안드로이드 고정 서명 키 등록하기

안드로이드 APK를 늘 같은 키로 서명하게 해서, 새 APK를 기존 앱을 지우지 않고 **덮어 설치**할 수 있게 해요. 덮어 설치하면 태블릿에 쓴 노트가 그대로 남아요. 키는 Claude가 만들어 **파일 두 개**로 건네요. Claude는 이 저장소의 GitHub 설정을 직접 바꿀 수 없어요(권한이 없어요). 그래서 GitHub에 넣는 일은 직접 해 주세요.

- **소요 시간**: 약 15분 (APK 만들기 약 10분 빼고)
- **끝나면 Claude에게 알려줄 것**: 시크릿 4개와 변수 1개를 등록했는지, 새 APK 실행의 **Summary**에 보이는 '서명:' 줄, 두 파일을 따로 보관했는지(보관한 곳은 알려 주지 않아도 돼요)

## 준비물

- Claude가 대화에 첨부한 파일 두 개: `noteapp-signing-secrets.txt`, `noteapp-sideload.p12`
- 저장소 주인 GitHub 계정과 브라우저(컴퓨터가 편하지만 iPad도 돼요)
- 두 파일을 따로 보관할 곳(비밀번호 관리자, 개인 클라우드 드라이브 등)

## 먼저 알아 둘 것

- 이 키는 태블릿에 직접 설치(사이드로드)하는 시험용이에요. Play 스토어에 올릴 때는 따로 정해요.
- **두 파일을 잃어버리면 같은 키로 다시 서명할 수 없어요.** 그러면 다음 APK를 덮어 설치할 수 없어서 앱을 지우고 다시 설치해야 하고, 그때 태블릿의 노트가 사라져요. 꼭 따로 보관해 주세요.
- 두 파일의 내용을 채팅에 붙여 넣지 마세요. Claude에게는 인증서 지문(누구에게 보여도 되는 값)만 알려 주면 돼요.
- `noteapp-signing-secrets.txt`의 비밀번호는 영문자와 숫자로만 되어 있어요. 값을 고치지 말고 그대로 붙여 넣어요.

## 따라 하기

### 1단계 — 파일 두 개 받기

1. 대화에 첨부된 `noteapp-signing-secrets.txt`와 `noteapp-sideload.p12`를 내려받아요.
2. `noteapp-signing-secrets.txt`를 메모 앱으로 열어요. `이름=값` 모양의 줄이 다섯 개 있어요.
3. 마지막 줄 `ANDROID_CERT_SHA256`의 값이 Claude가 대화에 적은 인증서 지문과 같은지 봐요.

### 2단계 — 시크릿 4개 등록

1. GitHub 저장소 → **Settings** → 왼쪽 **Secrets and variables** → **Actions**를 눌러요.
2. **Secrets** 탭에서 **New repository secret**을 눌러요.
3. **Name** 칸에 아래 이름을, **Secret** 칸에 파일의 같은 이름 줄에서 `=` 뒤 값을 넣고 **Add secret**을 눌러요. 네 번 되풀이해요.

| Name 칸 | Secret 칸 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | 파일의 `ANDROID_KEYSTORE_BASE64=` 뒤 값 — 아주 긴 한 줄이에요. 끝까지 모두 |
| `ANDROID_KEYSTORE_PASSWORD` | 파일의 `ANDROID_KEYSTORE_PASSWORD=` 뒤 값 |
| `ANDROID_KEY_ALIAS` | 파일의 `ANDROID_KEY_ALIAS=` 뒤 값 |
| `ANDROID_KEY_PASSWORD` | 파일의 `ANDROID_KEY_PASSWORD=` 뒤 값 |

값을 붙여 넣을 때 **앞뒤 공백이나 줄바꿈이 들어가지 않게** 해요. 이름은 대문자 그대로, 글자 하나도 다르면 안 돼요.

### 3단계 — 변수 1개 등록

1. 같은 화면의 **Variables** 탭에서 **New repository variable**을 눌러요.
2. **Name** 칸에 `ANDROID_CERT_SHA256`, **Value** 칸에 파일의 `ANDROID_CERT_SHA256=` 뒤 값을 넣고 **Add variable**을 눌러요.

변수가 있으면 CI는 '이 저장소는 고정 키를 써요'로 알아들어요. 그 뒤로 시크릿이 하나라도 빠지면 덮어 설치할 수 없는 APK를 만들지 않고 실패해요.

### 4단계 — 두 파일 따로 보관

1. 두 파일을 비밀번호 관리자나 개인 클라우드 드라이브에 함께 넣어요.
2. 다운로드 폴더에 남은 사본은 지워요.

### 5단계 — 새 APK 만들기

[05. 안드로이드 APK 설치하기](05-android-apk.md)의 1단계처럼 **Actions** → **Android APK** → **Run workflow**를 눌러요.

## 확인 방법

- 실행이 녹색 체크로 끝나요.
- 실행 **Summary**에 '서명: 고정 키 (…)' 줄이 보여요. 괄호 안은 인증서 지문의 앞 16자예요.
- **Releases**에 올라간 파일 이름이 `noteapp-apk-<번호>`.apk예요. `noteapp-debug-signed-<번호>`.apk이면 아직 고정 키가 아니에요.
- 확인되면 Claude에게 알려 주세요. Claude가 작업 컨테이너에 남은 키와 두 파일을 지워요.
- 이 APK를 처음 설치할 때 한 번만 기존 앱을 지우고 설치해요. 그 뒤로는 덮어 설치해요(05의 '새 버전으로 바꿀 때').

## 문제 해결

| 증상 | 해결 |
|---|---|
| 실행이 '고정 키 서명 재료가 없어요'로 실패해요 | 시크릿 4개 중 하나가 없거나 이름이 틀렸어요(삭제·오타). 2단계 표의 이름과 하나씩 맞춰 보고, 틀린 것은 지우고 다시 만들어요. APK는 만들어지지 않았으니 설치할 것도 없어요. |
| 실행이 '… ANDROID_CERT_SHA256와 달라요'로 실패해요 | 시크릿에 다른 키가 들어 있어요(시크릿이 바뀌었어요). 파일의 값으로 시크릿 4개와 변수를 다시 넣어요. |
| **Summary**가 '서명: debug 키 …'예요 | 시크릿과 변수가 아직 하나도 없어요. 2단계·3단계를 해요. |
| 값을 붙여 넣었는데 실패해요 | 값 앞뒤에 공백이나 줄바꿈이 들어갔을 수 있어요. 그 시크릿을 지우고, 메모 앱에서 `=` 뒤 값만 다시 복사해 넣어요. |
| 두 파일을 잃어버렸어요 | Claude에게 알려 주세요. 새 키를 만들면 한 번은 앱을 지우고 다시 설치해야 해요. 그 전에 앱에서 백업 내보내기를 먼저 해요. |
| 화면이 안내서와 달라요 | 스크린샷을 보내 주세요. 안내서를 고쳐 드릴게요. |
