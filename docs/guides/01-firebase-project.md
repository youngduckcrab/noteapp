# 01. Firebase 프로젝트 만들기

**2차 라운드에서는 Hosting만 써요 — Spark(무료) 요금제, 결제 계정 없음. 동기화·로그인·서버 함수(Blaze)는 나중의 실연결 단계에서 따로 켜요.** Hosting(Spark)은 실연결이 아니에요. 웹사이트를 올려 iPad에서 시험할 수 있게 할 뿐, 노트는 지금처럼 기기 안에만 저장돼요.

순서는 Spark로 프로젝트 만들기 → Hosting 시작 → [02](02-github-secrets.md)로 GitHub에 배포 키 연결이에요(02까지 약 15분). 앱을 올려 둘 Firebase 프로젝트를 만들고 Hosting(웹사이트 올리기)을 켜요. 실제로 올리는 일(CLI·배포)은 GitHub Actions가 하니까 콘솔에서는 프로젝트만 만들면 돼요.

- **소요 시간**: 약 10분 (02까지 약 15분)
- **끝나면 Claude에게 알려줄 것**: 프로젝트 ID (예: `noteapp-1a2b3`), 요금제가 Spark(무료)인지

## 준비물

- Google 계정 (개인 Gmail 계정을 권장해요. 회사·학교 계정은 조직 정책 때문에 02에서 막힐 수 있어요)
- 컴퓨터 브라우저 (iPad Safari로도 되지만 화면이 넓은 쪽이 편해요)

## 따라 하기

### 1단계 — Firebase 콘솔 열기

1. 브라우저에서 <https://console.firebase.google.com> 을 열어요.
2. Google 계정으로 로그인해요. 처음이면 약관 동의 화면이 나와요.

### 2단계 — 프로젝트 만들기

1. **프로젝트 추가**(화면에 따라 **프로젝트 만들기** 또는 **Firebase 프로젝트 시작하기**)를 눌러요.
2. 프로젝트 이름을 입력해요. 예: `noteapp`.
3. 이름 아래에 작게 보이는 **프로젝트 ID**를 확인해요. 웹 주소(`<프로젝트 ID>.web.app`)가 되고 **나중에 바꿀 수 없어요.** 바꾸고 싶으면 그 옆 연필 아이콘을 눌러요.
4. **계속**을 눌러요.
5. **Google 애널리틱스** 화면에서 스위치를 **꺼요**(이 앱은 쓰지 않아요).
6. **프로젝트 만들기**를 누르고, 끝나면 **계속**을 눌러요.

### 3단계 — Hosting 시작하기

1. 왼쪽 메뉴에서 **빌드** → **Hosting**을 눌러요. 메뉴가 안 보이면 콘솔 위 검색창에 'Hosting'을 입력해요.
2. **시작하기**를 눌러요.
3. 'Firebase CLI 설치', '프로젝트 초기화', '배포' 안내가 차례로 나와요. 명령어는 따라 하지 않아도 돼요(Claude와 GitHub Actions가 처리해요). **다음** / **계속**만 눌러 끝까지 가요.

### 4단계 — 프로젝트 ID 확인

1. 왼쪽 위 톱니바퀴(⚙) → **프로젝트 설정**을 눌러요.
2. **일반** 탭의 **프로젝트 ID**를 복사해 Claude에게 보내 주세요.

### 5단계 — 요금제 확인

1. 왼쪽 메뉴 아래쪽에 요금제 이름이 보여요. **Spark**(무료)이면 그대로 두면 돼요.
2. **Blaze**로 되어 있으면 사용한 만큼 요금이 나올 수 있어요. 바로 [03. 예산 알림 설정하기](03-budget-alert.md)를 따라 해 주세요.

## 실연결 때 정할 것 (지금은 하지 않음)

동기화·로그인(M4 — 실연결 단계)을 연결할 때 Firestore 데이터베이스·Cloud Storage·Authentication·서버 함수(Functions, Blaze 요금제)를 켜요. **2차 라운드에서는 하지 마세요.** 미리 알아 둘 것만 적어요.

- **Firestore 데이터베이스 위치**: `asia-northeast3`(서울)을 권장해요. iPad와 가까워 빨라요.
- **Cloud Storage 버킷 위치**: 무료 사용량 조건 때문에 US 리전(예: `us-central1`)을 권장해요.
- 두 위치 모두 **만든 뒤에는 바꿀 수 없어요.**
- 무료 사용량 조건은 이 안내서를 쓸 때의 기억이라 확실하지 않아요(미확인). 만들기 전에 콘솔의 안내 문구를 다시 확인해요.
- 최종 선택은 직접 해요. 고르기 어려우면 Claude에게 물어보세요.
- **Google 로그인**(Authentication)을 켤 때 `authDomain`은 앱이 서비스되는 Hosting 주소 `<프로젝트 ID>.web.app`으로 둬요. **Authentication → 설정 → 승인된 도메인**에 live 주소(`<프로젝트 ID>.web.app`)가 있는지 확인해요. 자세한 절차는 M4 때 이 안내서를 고쳐서 알려 드릴게요.

## 확인 방법

- Firebase 콘솔 첫 화면에 만든 프로젝트가 보여요.
- **Hosting** 화면에 `<프로젝트 ID>.web.app` 도메인이 보여요(첫 배포 전에는 '사이트가 비어 있음' 같은 안내가 보일 수 있어요).
- 왼쪽 아래 요금제가 **Spark**예요.

## 문제 해결

| 증상 | 해결 |
|---|---|
| '프로젝트 ID가 이미 사용 중' | 프로젝트 ID 옆 연필 아이콘을 눌러 다른 ID를 정해요. |
| 프로젝트를 더 만들 수 없다는 안내 | 계정당 만들 수 있는 프로젝트 수에 한도가 있어요. 쓰지 않는 프로젝트를 지우거나 Claude에게 알려 주세요. |
| 왼쪽 메뉴에 **Hosting**이 안 보여요 | 콘솔 위 검색창에 'Hosting'을 입력해요. 메뉴가 접혀 있으면 **빌드**를 눌러 펼쳐요. |
| 요금제를 바꾸라는 화면이 나와요 | Hosting은 Spark에서 쓸 수 있어요. 바꾸지 말고 닫은 뒤 Claude에게 알려 주세요. |
| 화면이 안내서와 달라요 | 스크린샷을 보내 주세요. 안내서를 고쳐 드릴게요. |
