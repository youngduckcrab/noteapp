# 04. iPad에서 웹 버전 시험하기

iPad Safari로 테스트 주소를 열고 홈 화면에 추가해 써 보는 방법, 새 버전 받기, 백업, 문제가 생겼을 때 알려 주는 방법이에요. 맨 아래 체크리스트로 결과를 알려 주세요.

- **소요 시간**: 처음 약 15분, 체크리스트 전체는 약 30분
- **끝나면 Claude에게 알려줄 것**: 체크리스트 번호별 결과(통과 / 실패 / 기록한 값), 설정 → 저장 공간의 '영구 보관' 값, 백업 결과(18a·18b), 문제가 있었으면 '진단 정보 복사'로 복사한 내용

## 준비물

- iPad (Safari)와 Apple Pencil
- 테스트 주소 — 1단계에서 찾아요
- GitHub 이슈로 알려 주고 싶으면 GitHub 계정(채팅으로 알려 줘도 돼요)

## 먼저 알아 둘 것

- **웹 버전은 테스트 전용이에요. 중요한 노트는 쓰지 마세요.** 브라우저가 저장 공간을 지우면 노트가 사라질 수 있어요.
- **필기는 홈 화면 앱으로 해요.** Safari 탭에서는 화면 왼쪽 가장자리에서 밀면 '뒤로 가기'가 일어날 수 있어요. 홈 화면에 추가한 앱에는 이 동작이 없어요.
- **미리보기 주소는 live 주소와 데이터·홈 화면 앱·로그인이 모두 따로예요.** 미리보기 주소에서 쓴 노트는 live 주소에서 보이지 않아요. 미리보기 주소는 **임시**라서 7일 뒤 주소가 사라지면 그 데이터도 다시 쓸 수 없어요.
- 로그인·동기화 확인(M4)은 live 주소에서만 해요.

## 따라 하기

### 1단계 — 주소 찾기

| 주소 | 어디서 찾나요 | 언제 쓰나요 |
|---|---|---|
| live 주소 `https://<프로젝트 ID>.web.app` | 고정 주소예요. 01의 프로젝트 ID를 넣으면 돼요 | 평소 시험, 홈 화면에 추가할 주소 |
| 브랜치 미리보기 주소 `https://<프로젝트 ID>--b-….web.app` | GitHub 저장소 → **Actions** → **CI** → 해당 실행 → **Summary**의 '주소:' 줄 | Claude가 '이 주소로 확인해 주세요'라고 할 때만. 7일 동안만 열려요 |

### 2단계 — Safari로 열기

1. Safari 주소창에 주소를 입력해 열어요.
2. 가운데에 '필기노트'와 '불러오는 중…'이 잠깐 보이고 라이브러리 화면이 나와요.

### 3단계 — 홈 화면에 추가

1. Safari 위쪽의 공유 버튼(네모에 위쪽 화살표)을 눌러요.
2. **홈 화면에 추가**를 눌러요(목록 아래쪽에 있어요).
3. 이름은 '필기노트' 그대로 두고 **추가**를 눌러요.
4. 홈 화면의 필기노트 아이콘으로 실행해요. 주소창 없이 전체 화면으로 열려요.

홈 화면 앱과 Safari 탭은 저장 공간이 따로일 수 있어요(미확인). 노트는 홈 화면 앱에서만 써 주세요.

### 4단계 — 빌드 라벨 확인

1. 라이브러리 화면의 **설정**(톱니바퀴)을 눌러요.
2. **앱 정보**의 **빌드** 줄을 봐요. 예: `0.1.0 (#42 · a1b2c3d · main)` — `#` 뒤 숫자가 빌드 번호예요.
3. **홈 화면 앱** 줄이 '예'인지 봐요(Safari 탭에서 열었으면 '아니요').

### 5단계 — 새 버전 받기

- 새 버전이 배포된 뒤 앱으로 돌아오면 1분 안에 화면 위쪽에 '새 버전이 나왔어요 (#43 · b2c3d4e). 새로고침하면 적용돼요.' 배너가 떠요.
- **새로고침**을 누르면 쓰던 내용을 저장한 뒤 새 버전으로 다시 열려요. **나중에**를 누르면 그 버전은 다시 알리지 않아요.
- 필기 중에 끊기지 않도록 저절로 새로고침하지는 않아요.
- 바로 확인하고 싶으면 **설정 → 앱 정보 → 새 버전 확인**을 눌러요.

### 6단계 — 홈 화면 앱 완전히 끄기

1. 화면 맨 아래에서 위로 천천히 밀다가 멈춰 앱 전환 화면을 열어요.
2. 필기노트 카드를 위로 밀어 올려요.
3. 홈 화면 아이콘으로 다시 실행해요.

### 7단계 — 저장 공간 확인

1. **설정 → 저장 공간**을 열어요.
2. **영구 보관** 줄을 봐요.
   - '허용됨': 저장 공간이 부족해도 브라우저가 노트를 함부로 지우지 않아요.
   - '허용되지 않음 — 공간이 부족하면 브라우저가 지울 수 있어요': 백업을 자주 해 주세요.
3. 어느 쪽인지 Claude에게 알려 주세요.

### 8단계 — 백업 내보내기

노트를 파일 하나(`noteapp-backup-날짜-시각.json`)로 만들어 iPad의 파일 앱에 보관해요.

1. **설정 → 앱 정보 → 백업 내보내기**를 눌러요.
2. '백업을 만드는 중…'이 잠깐 보이고 '백업 파일이 준비됐어요' 창이 올라와요. 두 버튼 중 하나를 눌러요.
   - **[내려받기]**: 파일 앱의 **다운로드** 폴더에 저장돼요.
   - **[공유 · 파일에 저장]**: 공유 시트가 열려요. **파일에 저장**을 누르고 위치를 골라 **저장**해요.
3. **홈 화면 앱에서는 [내려받기]가 아무 일도 하지 않을 수 있어요(미확인).** 그때는 **[공유 · 파일에 저장]**을 써요.
4. **두 버튼 모두 안 되면 아직 백업을 할 수 없는 상태예요. 바로 알려 주세요.**
5. 백업을 만드는 중에 '저장이 늦어지고 있어요. 저장 공간을 확인해 주세요.'가 뜨고 끝나지 않으면 **[취소]**를 눌러요. 노트 저장이 다시 시도되는 중이라는 뜻이에요. **설정 → 저장 공간**을 확인하고, **앱 정보 → 진단 정보 복사**로 복사한 내용을 보내 주세요.
6. 백업은 노트를 쓴 곳에서 해요. 홈 화면 앱과 Safari 탭은 저장 공간이 따로일 수 있어서(미확인) Safari 탭에서 백업하면 홈 화면 앱의 노트가 들어가지 않을 수 있어요.

### 9단계 — 문제 알려 주기 (피드백)

- **진단 정보**: **설정 → 앱 정보 → 진단 정보 복사**를 누른 뒤 채팅에 붙여 넣어요. 빌드·브라우저·시작 시간·저장소 정보가 들어 있어요.
- **GitHub 이슈**: 저장소 → **Issues** → **New issue** → **피드백** 양식을 채워요([양식 내용](../../.github/ISSUE_TEMPLATE/feedback.yml)). 스크린샷·화면 녹화는 칸에 끌어다 놓으면 돼요.
- **iPad 모델**: iPad **설정 → 일반 → 정보 → 모델 이름**을 봐요.
- **펜슬 종류**: Apple Pencil Pro, Apple Pencil(2세대), Apple Pencil(USB-C) 등 상자나 구입 내역의 이름을 적어 주세요. iPad **설정 → Apple Pencil** 화면에서도 단서를 볼 수 있어요.

## 문제 해결

| 증상 | 해결 |
|---|---|
| 흰 화면이나 '불러오는 중…'에서 멈춰요 | 30초까지 기다려요. '30초 안에 앱이 시작되지 않았어요.'와 **새로고침** 버튼이 나오면 눌러요. |
| '앱을 시작하지 못했어요' 화면 | **다시 시도**를 눌러요. 그래도 같으면 **진단 정보 복사**를 눌러 채팅에 붙여 넣어 주세요. 새로고침 버튼이 있으면 눌러 최신 버전을 받아요. |
| '이 브라우저에서는 저장소를 쓸 수 없어요…' | 개인정보 보호(비공개) 탭이면 일반 탭이나 홈 화면 앱으로 열어요. |
| 옛 버전이 보여요 (빌드 번호가 그대로) | 앱을 완전히 껐다가(6단계) 다시 열거나 **설정 → 앱 정보 → 새 버전 확인**을 눌러요. |
| 미리보기 주소가 열리지 않아요 | 7일이 지나 사라졌을 수 있어요. Actions의 새 실행에서 주소를 다시 찾거나 Claude에게 알려 주세요. |
| 백업 버튼이 둘 다 안 돼요 | 8단계 4번처럼 바로 알려 주세요. |
| 마지막 수단: 데이터 지우기 | 위 방법이 모두 안 될 때만 해요. **테스트 노트가 모두 지워져요.** 시작 오류 화면의 **이 기기 데이터 지우고 다시 시작**을 누르거나, iPad **설정 → (앱 →) Safari → 고급 → 웹사이트 데이터**에서 테스트 주소를 지워요(메뉴 위치는 iPadOS 버전에 따라 달라요 — 미확인). 지우기 전에 진단 정보를 먼저 보내 주세요. |
| 화면이 안내서와 달라요 | 스크린샷을 보내 주세요. 안내서를 고쳐 드릴게요. |
