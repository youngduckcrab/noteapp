# feature_markdown — MD 문서 screen (MD area). Plan: [docs/plans/m5-7/08-markdown.md](../../docs/plans/m5-7/08-markdown.md)

The rendered view (보기) and the source editor (편집) of an MD 문서 — a note whose format is markdown, its text kept byte for byte in note_core (`MarkdownRepository`). Rendering uses dart-lang's pure-Dart `markdown` parser (GFM) and the package's own widgets; math goes through ink_engine's `MathPreview`; colours come only from ui_kit's `StyleTokens` / `ColorScheme`. Plugin free (R16): files, sharing and opening links are the app's slots in `lib/slots.dart`. Two entry points: `feature_markdown.dart` (`MarkdownScreen`, `MarkdownKeys` — imported `deferred` by the app on the web, because the parser is about 59 KB gzip) and `slots.dart` (slot providers only, no parser — imported eagerly). State: Track B screen (08-markdown 8, B-1 … B-14).

Layout of `lib/src/`: `parse/` (block splitter with source ranges, per-block parsing on one shared markdown `Document`, math and raw-HTML syntaxes, task-box source scan, block keys), `render/` (lazy `ListView.builder` view and the block / inline / code / table / math / image / link renderers, colours from `StyleTokens` only), `edit/` (monospace editor and symbol row, `LineEndingCodec`, autosave timing), `screen/` (`MarkdownController` — the single owner of the open document's buffer, base version and save state — and the banners), `strings_ko.dart`.

Rules worth knowing: remote images are never fetched and links never open by themselves (a sheet asks; opening goes through the app's `markdownOpenLinkProvider` and only for http, https, mailto, tel); every change (typing, task boxes, restoring unsaved text) goes through the buffer and `saveText(baseVersion:)`, so another device's text is never overwritten silently; all positions (task boxes, search landing, block ranges) are offsets in the decoded text (no BOM, LF only). Tests: `flutter test --exclude-tags perf` (goldens in `test/goldens`, Ahem font); performance: `flutter test --run-skipped -t perf`.
