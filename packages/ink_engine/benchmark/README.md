# ink_engine 벤치마크 (03-ink 9.1 B1–B11, T22)

계획서 9.1 벤치마크 표의 VM 기준값을 확인한다. `benchmark/`는 `test/` 밖이라
`flutter test`·`ws test` 기본 실행에 들어가지 않는다(모든 파일 `@Tags(['bench'])`,
`dart_test.yaml`에 `bench` 선언).

## 실행

```sh
cd packages/ink_engine
flutter test benchmark/ --concurrency=1          # VM — 9.1 기준값을 expect로 판정
flutter test benchmark/ --concurrency=1 --platform chrome   # 참고용(기준 판정 없음)
```

- `--concurrency=1`: 파일끼리 CPU를 나눠 쓰지 않게 한다.
- 같은 컨테이너에서 다른 작업이 돌면 수치가 1.5~2배까지 흔들린다. 미달이 나오면 부하가
  낮을 때 한 번 다시 돌린다(`uptime`의 load가 CPU 수 4보다 작을 때).
- `flutter test`는 JIT + assert 켜진 디버그 VM이다(CORE `rawData`가 디버그에서 뷰를 새로
  만드는 것 등 포함). iPad 릴리스(AOT) 수치와 다르며, 9.1 기준값도 이 조건의 값이다.

## 출력

케이스마다 JSON 한 줄:

```json
{"bench":"B1","case":"outline 200 pt (fountain)","platform":"vm","runs":30,
 "median_ms":0.072,"mean_ms":0.073,"p95_ms":0.09,"max_ms":0.096,"min_ms":0.055,
 "criteria":{"median_ms":0.15},"pass":true,"outline_vertices":453}
```

`criteria`는 판정에 쓰는 통계와 기준(ms)이다. VM에서는 기준을 넘으면 테스트가 실패하고,
웹에서는 출력만 한다. `criteria`가 빈 케이스는 참고용이다.

## 작업량과 판정

| ID | 측정 | 작업량 | 기준 (9.1) | 판정 통계 |
|---|---|---|---|---|
| B1 | `OutlineGenerator.outline` | 만년필 필기선 200점 / 1000점(고리 모양, widthQ 0.2–0.3) | ≤ 0.15 / ≤ 0.5 ms | 중앙값(40회 평균 × 30) |
| B2 | 라이브 샘플 1개: `StrokeSession.addSample` + `live.frozenPath`·`tailPath` | 만년필 2000샘플 한 획(240Hz, 필압 변화), 워밍업 2획 + 측정 5획 | 평균 ≤ 0.3, 최대 ≤ 1.0 ms | 평균(1만 샘플) / 최대 = 샘플 위치별 5획 중 최솟값의 최대 |
| B3 | 페이지 수용: `updateContent` + inkBase 첫 paint(외곽선 + 청크 기록) | 획 2000개 × 150점, 새 컨트롤러·새 CORE 객체 | ≤ 500 ms | 중앙값 |
| B4 | 지우개 이동 1회(`EraserSession.addSample` — 색인 질의 + 정밀 판정) | 혼합 획 1만 개 A4, 반지름 8pt, 2–4pt 간격 문지름 400샘플 × 4회 | ≤ 0.3 ms | 평균 |
| B5 | 부분 지우개: 닿은 획 50개의 구간(P2–P4) + 조각(P5/P6) + CORE 조각(`fromInterleaved`) | 150점 가로선 50개, 세로 한 번 | ≤ 2 ms | 중앙값 |
| B5 (참고) | 같은 작업을 컨트롤러 제스처로(begin + 이동 + end, P8 미리보기 조각 포함) | 같음 | — | — |
| B6 | 올가미 `end()`(L2 다각형 + 후보 + L5 포함 판정 + z 정렬 + 선택) | 혼합 획 1만 개, 400꼭짓점 별 모양(반지름 205/235pt 교대, 페이지 30%) | ≤ 25 ms | 중앙값 |
| B7 | `StrokeSpatialIndex.of` | 혼합 획 1만 개 | ≤ 15 ms | 중앙값 |
| B8 | 청크 재기록: 가운데 획 하나 제거/복원 → `updateContent` + inkBase paint | 한 청크(256pt)에 획 1000개 | ≤ 8 ms | 중앙값 |
| B9 | `InkVectorExport.exportStrokes` | 혼합 획 2000개(볼펜 80%·만년필 10%·형광펜 10%) | ≤ 300 ms | 중앙값 |
| B10 | `InkPageThumbnailRenderer.render` (512px PNG, 4ms마다 양보 포함) | 혼합 획 3000개 + 줄 노트 속지 | ≤ 600 ms | 중앙값 |
| B11 | `InkPageContent.fromCore` (정렬된 입력, `InkStroke.of`) | 획 1만 개(매번 새 CORE 객체) | ≤ 5 ms | 중앙값 |

혼합 획 = `InkDevTools.syntheticStrokes`(점 40–160개, 평균 100). B2의 최대는 GC 멈춤이나
다른 프로세스의 선점이 무작위로 한 획에만 걸리는 것을 빼려고 샘플 위치마다 5획 중 가장 빠른
값을 취한 뒤 그 최댓값을 본다(파이프라인 자체 비용 — 청크 고정, 긴 꼬리 — 은 5획 모두에
걸린다). 걸러지지 않은 최댓값(`raw_max_ms`)과 p99(`raw_p99_ms`)도 함께 출력한다.

## T22에서 바꾼 것 (결과는 그대로 — 기존 테스트·골든·체크섬 통과)

| 대상 | 내용 | 효과 |
|---|---|---|
| `OutlineGenerator` (B1·B3·B9·B10) | O4 측면 점을 `List<double>`(박싱) 대신 `Float64List` 버퍼에, 굽힘의 안쪽 면과 작은 굽힘(조르당 부등식으로 `segments ≤ 1`이 확실할 때)은 `atan2`를 건너뜀, O8 RDP를 클로저 없이 인라인 + 제곱 거리가 지금까지의 최대 이하이면 `sqrt` 생략(단조성으로 같은 선택) | 1000점 0.6 → 0.36 ms. 바꾸기 전 구현과 획 2302개(펜 5종·합성·필기선)의 다각형이 비트 단위로 같음을 확인 |
| `StrokeOutline.toPath` (B8) | 외곽선마다 `ui.Path`를 한 번만 만들어 공유(L1 항목 바이트에 경로 몫 17B/정점 + 96B를 더해 셈) | 청크 재기록 22 → 1.7 ms (경로 만들기가 대부분이었음) |
| `StrokeOutline.toVectorPath` (B9) | `List<double>.addAll([...])` 대신 크기를 먼저 세어 `Float32List`·`Uint8List`에 바로 씀 | 2000획 268 → 120 ms |
| 올가미 (B6) | 획 bounds가 다각형 안/밖에 통째로 있으면(어떤 변도 닿지 않음) 점 검사 없이 1/0, 아니면 16구간씩 bounds로 같은 판정, 남은 길이로 `coverage`에 못 닿으면 바로 false, 띠 안의 변을 오른쪽 끝 순으로 정렬해 일찍 멈춤, y 띠와 x 띠(−90° 회전 좌표의 같은 Sunday 판정) 중 변이 적은 쪽, z는 고른 획마다 한 번만 조회 | 71 → 약 20 ms. 판정은 `coverageOf ≥ coverage`와 같음(획 1500개 × 다각형 3종 × coverage 4종 테스트) |
| 부분 지우개 (B5) | 구간 탐색에 획 최대 반지름으로 먼저 거르기, 조각 데이터를 원본 점에서 한 번에 복사, `end()`의 CORE 조각이 미리보기 조각의 `StrokePoints`를 그대로 씀(두 번째 `fromInterleaved` 없음) | 제스처 2.4 → 1.4 ms (부하 적을 때) |
